# 카페 판매·재고·비용 관리 제품 요구사항 문서(PRD)

- 작성일: 2026-10-12
- 상태: 자료 확인 및 사용자 결정 전 초안
- PRD란: 프로그램이 누구의 어떤 문제를 해결하고, 처음 어디까지 만들지 정리한 문서
- 이번 문서에서는 계산식, 화면 디자인, 기술 선택, 상세 동작, 코드를 정하지 않는다.

## 1. 자료 확인 결과와 주의점

현재 작업 폴더가 비어 있고, 요청에 언급된 엑셀·JSON·데이터설명.md의 내용을 확인할 수 없다. 따라서 기록 종류, 항목, 기간, 건수, 누락 여부에 대한 자료 기반 사실은 아직 없다. 아래 요구사항은 사용자 요청에 근거하며, 자료 분석 결과로 취급하지 않는다.

자료를 받은 뒤 확인할 항목:

| 확인 대상 | 확인 이유 |
| --- | --- |
| 판매 기록의 날짜·메뉴·수량·금액 및 취소·환불 기록 | 판매 실적과 메뉴 수익성을 연결할 수 있는지 확인 |
| 메뉴별 사용 재료와 사용량, 재료 가격 | 판매만으로는 재료 비용과 잔량을 알 수 없으므로 연결 정보 확인 |
| 재료 수량의 단위와 구매 포장 단위 | 예: 우유 1팩과 1,000mL를 같은 수량으로 취급하지 않기 위해 확인 |
| 비용 기록의 종류·발생 기간 및 재료 구매 기록 | 같은 지출이 손익에 두 번 반영될 가능성 확인 |
| 입고·폐기·실제 재고·시작 재고와 기록 시점 | 기록으로 추정한 잔량과 실제로 센 잔량을 구분하기 위해 확인 |
| 엑셀과 JSON의 관계 및 중복 기록 | 같은 기록인지 별도 기록인지 확인 |
| 메뉴·재료 이름 또는 식별 정보, 누락·중복·오류 | 기록 간 연결 가능성과 자료 정리 작업량 확인 |
| 데이터설명.md의 용어 정의와 기록 규칙 | 자료 작성자의 의미와 프로그램의 해석이 일치하는지 확인 |

기획 시 주의할 점은 메뉴 수익성과 매장 전체 손익을 구분하는 것, 실제 기록과 예상치를 구분하는 것, 정보가 부족한 결과를 확정된 숫자처럼 보이지 않게 하는 것이다. 구체적인 기준은 자료 확인과 사용자 결정 후 정한다.

## 2. 확인된 요구와 미정 사항

### 사용자 요청으로 확인된 요구

- 카페의 판매·재고·비용을 관리하는 웹 프로그램이 필요하다.
- 판매·비용 기록을 직접 입력·수정·삭제하고 싶다.
- 엑셀 양식을 내려받고 기록을 가져오고 싶다.
- 메뉴별 수익성, 기간별 실적과 예상 손익을 확인하고 싶다.
- 재료의 입고·폐기·실제 재고를 기록하고 부족한 재료와 필요한 발주량을 참고하고 싶다.
- 일·주·월·분기·반기·연간 조회와 저장·백업·복원이 필요하다.
- 1차 구현은 기획·화면 설계·개발·검사·배포를 합쳐 4시간 안에 가능한 수준이어야 한다.

### 아직 정하지 않은 사항

- 자료에 실제로 존재하는 항목, 품질, 기간, 규모와 가져오기 가능 여부
- 한 사람·한 기기에서 쓰는지, 여러 사람·기기에서 함께 쓰는지
- 메뉴 수익성에 포함할 비용과 매장 손익의 의미
- 기록에 따른 손익과 예상 손익의 구분 및 예상의 근거
- 메뉴별 재료 정보와 시작 재고를 확보할 방법
- 재료 부족의 판단 기준과 실제 재고 기록의 의미
- 1차에 지원할 엑셀 기록 종류와 기존 자료 이전 범위
- 1차 기간 조회 범위와 주·분기·반기의 경계
- 저장·백업·복원의 사용 범위
- 아래 1차·2차 범위 제안에 대한 사용자 수락

## 3. 제품 목표와 핵심 흐름

매장 운영자가 판매를 기록한 뒤 어떤 메뉴가 수익에 도움이 되는지, 선택한 기간의 매장 손익은 어떤지, 어떤 재료가 부족한지 이어서 확인하도록 돕는다.

핵심 흐름:

1. 분석에 필요한 메뉴·재료·비용·시작 재고 정보를 준비한다.
2. 판매 기록을 입력한다.
3. 메뉴별 판매 실적과 수익성을 확인한다.
4. 같은 기간의 매장 손익과 재료 잔량·부족 여부를 확인한다.
5. 잘못된 판매 또는 비용 기록을 고치고 결과를 다시 확인한다.
6. 기록을 저장하고 백업·복원할 수 있다.

1번에 필요한 자료가 없는 경우 이를 확보하는 작업도 구현 시간에 영향을 준다. 없는 자료를 임의로 채워 결과를 확정하지 않는다.

## 4. 1차 구현 제안 — 최소 핵심 기능(MVP)

MVP는 실제 운영 흐름을 끝까지 확인할 수 있는 가장 작은 첫 버전이다. 아래는 확정 사항이 아닌 범위 제안이다. 한 매장, 한 명의 주 사용자를 출발점으로 제안하되 사용 환경은 사용자에게 확인한다.

| 기능 | 1차 제안 범위 | 사용자가 얻는 결과 |
| --- | --- | --- |
| 기초 정보 | 핵심 흐름에 필요한 메뉴·재료·메뉴별 사용 재료·가격·시작 재고를 준비하고 필수 정보 수정 지원 | 분석에 필요한 근거 확보 |
| 판매 관리 | 판매 기록 입력·수정·삭제·조회 | 일상적인 판매 기록과 오류 수정 |
| 비용 관리 | 비용 기록 입력·수정·삭제·조회 | 매장 손익을 확인할 근거 확보 |
| 메뉴 수익성 | 자료가 준비된 메뉴의 판매 실적과 수익성 확인 | 메뉴 간 수익성 비교 |
| 기간별 실적·손익 | 일·월 조회를 우선 제안. 기록에 근거한 실적과 손익 확인 | 오늘과 이번 달의 운영 상황 파악 |
| 재료 관리 | 입고·폐기·실제 재고 기록, 잔량과 부족 여부 확인 | 판매 이후 재료 상황 확인 |
| 엑셀 기록 가져오기 | 판매 기록용 양식 다운로드와 그 양식의 기록 가져오기 우선 제안 | 판매 기록을 한꺼번에 입력 |
| 저장·백업·복원 | 사용 환경에 맞는 기본 저장, 전체 기록 백업·복원 | 기록을 이어 쓰고 백업으로 되돌리기 |

품질 요구:

- 판매·비용의 변경이 관련 실적·수익성·손익·재료 결과에 일관되게 반영되어야 한다.
- 기록 기반 결과, 추정 재고, 실제로 확인한 재고, 예상치를 혼동하지 않아야 한다.
- 필요한 정보가 없거나 잘못된 경우 결과를 정상적인 0으로 취급하지 않아야 한다.
- 엑셀 가져오기와 복원으로 잘못된 기록이나 중복이 생길 가능성을 다뤄야 한다. 세부 처리 방식은 후속 설계에서 정한다.
- 메뉴 수익성과 매장 손익의 의미를 비개발자도 이해할 수 있어야 한다.

## 5. 2차 구현 제안 — 확장 기능

| 기능 | 2차 제안 내용 | 미루는 이유 |
| --- | --- | --- |
| 기간 조회 확장 | 주·분기·반기·연간 조회 | 첫 버전은 일·월로 핵심 흐름 검증에 집중 |
| 예상 손익 | 미래 기간의 예상 실적·손익 | 예상의 근거와 사용자 입력에 대한 합의 필요 |
| 발주량 참고 | 부족 여부를 넘어 구매할 수량 제안 | 목표 재고, 구매 단위, 향후 판매 등의 기준 필요 |
| 엑셀 범위 확장 | 비용·입고·폐기·실제 재고 가져오기 | 기록별 자료 구조와 검사 범위가 늘어남 |
| 기존 자료 폭넓게 이전 | 다양한 기존 엑셀·JSON 기록의 이전 | 실제 자료 구조와 두 파일의 관계 확인 필요 |
| 사용 환경 확장 | 여러 사람·기기·매장 지원 | 공유 사용과 기록 충돌에 관한 요구 확인 필요 |
| 관리 편의 확장 | 자동 백업, 변경 이력, 추가 비교 분석 | 핵심 흐름 이후 필요성을 확인해 별도 결정 |

기존 자료를 읽어 기획하는 작업과 프로그램에 기존 자료 전체를 가져오는 기능은 별개의 범위다. 자료 분석 자체는 이번 기획에 필요하며, 전체 이전은 자료 확인 후 1차 포함 여부를 결정한다.

## 6. 4시간 구현을 위한 작업 배분 제안

| 작업 | 시간 | 완료 목표 |
| --- | --- | --- |
| 자료 확인·기획 결정 | 30분 | 필수 자료와 1차 범위 확정 |
| 화면 설계 | 20분 | 핵심 흐름을 사용할 수 있는 구성 마련 |
| 개발 | 125분 | 확정된 1차 기능 연결 |
| 검사 | 40분 | 핵심 흐름, 기록 변경, 가져오기, 저장·복원 확인 |
| 배포·사용 확인 | 25분 | 합의한 사용 환경에서 실행 확인 |
| 합계 | 240분 | 첫 버전 사용 가능 |

이는 견적 보장이 아닌 목표 배분이다. 자료가 준비되어 있고 사용 환경이 단순한 경우를 전제로 한다. 자료 정리·누락 정보 수집·복잡한 비용 기준·공유 사용이 필요하면 시간 내 가능성을 다시 검토한다. 검사나 배포 시간을 없애서 범위를 맞추지 않고 사용자와 기능 범위를 조정한다.

## 7. 1차 완료 판단 기준

- 준비된 메뉴의 판매를 입력한 뒤 메뉴 수익성, 같은 기간의 손익, 관련 재료 잔량을 이어서 확인할 수 있다.
- 판매와 비용을 수정·삭제한 뒤 관련 결과가 일관되게 달라진다.
- 입고·폐기·실제 재고를 기록하고 재료 상황을 확인할 수 있다.
- 합의된 기간 범위로 기록과 결과를 조회할 수 있다.
- 내려받은 판매 양식에 기록을 작성하여 가져올 수 있다.
- 기록 저장 후 다시 사용할 수 있고, 백업·복원 후 동일한 기록과 결과를 확인할 수 있다.
- 정보 누락과 잘못된 자료를 확인할 수 있으며, 준비되지 않은 분석을 확정된 결과로 오해하지 않는다.
- 합의한 사용 환경에 배포되어 핵심 흐름을 실제로 사용할 수 있다.

검사에 사용할 구체적인 예시 기록과 기대 결과는 자료 및 기준 합의 후 정한다. 이번 문서에는 계산식을 정하지 않는다.

## 8. 결정 진행 방식

현재 첫 단계는 엑셀·JSON·데이터설명.md 확보다. 자료를 읽기 전에는 자료에서 확인한 사실을 작성하지 않는다.

자료 확인 후 다음 순서로 한 번에 하나씩 질문하고, 답을 받을 때마다 문서를 갱신한다. 아래는 질문 순서 후보이며 일괄 답변을 요청하는 목록이 아니다.

1. 사용 환경: 예를 들어 사장 혼자 한 기기에서 쓰는 경우와 직원도 다른 기기에서 함께 쓰는 경우
2. 1차 범위: 예를 들어 일·월과 기록 기반 손익을 먼저 완성할지, 예상 손익을 위해 다른 기능을 줄일지
3. 수익성과 손익의 의미: 예를 들어 메뉴 재료비 중심으로 볼지, 다른 비용도 포함해 볼지
4. 재고와 부족 판단에 필요한 기준
5. 엑셀 가져오기 및 기존 기록 이전 범위
6. 저장·백업·복원 범위와 실제 사용 완료 조건

각 질문에는 쉬운 예시, 선택지, 추천 이유를 제공한다. 추천은 사용자 결정과 구분하고, 답변 전에는 확정 사항으로 바꾸지 않는다.
