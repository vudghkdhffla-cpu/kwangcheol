# 카페 판매·재고·비용 관리 기능 요구사항 문서(FRD)

- 작성일: 2026-10-12
- 상태: 결정 대기 초안. 구현 승인이나 계산 정책 확정 문서가 아니다.
- FRD란: 사용자가 어떤 행동을 하면 프로그램이 무엇을 처리하고 어떤 결과를 보여주어야 하는지 설명하는 문서다.
- 기준 문서: `docs/01_PRD.md`. `design/01_prd.md`는 내용이 같은 사본이다.
- 검토한 시안: `design/_1`~`_5`의 `code.html`과 `screen.png`, `design/artisan_ledger/DESIGN.md`.
- 보조 확인 자료: `data/데이터설명.md`, `data/매장운영데이터.json`. 엑셀 내부 내용은 이번 작업에서 별도로 대조하지 않았다.
- 이 문서에서 **요구**는 PRD에 명시된 기능·품질 요구, **제안**은 검토용 처리·계산 방법, **미정**은 사용자 결정이 필요한 부분, **보류**는 2차 또는 시안에만 있어 구현에 포함하지 않은 부분이다. 제안은 답변 없이 확정하지 않는다.

## 1. 프로그램의 기능과 핵심 사용 흐름

판매와 비용을 기록하고, 메뉴별 수익성을 확인한 뒤 같은 기간의 매장 손익과 재료 잔량을 확인하는 프로그램이다. 입고·폐기·실제 재고 기록으로 재료 상황을 관리하고, 엑셀 판매 양식과 기록 가져오기를 제공한다. 기록 저장·전체 백업·복원도 필요하다.

1. 메뉴, 가격, 재료, 레시피, 시작 재고를 준비한다. 레시피는 메뉴 1개에 필요한 재료와 수량이다.
2. 판매를 직접 입력하거나 판매 양식으로 가져온다.
3. 판매 금액과 수량을 확인하고 메뉴별 재료 비용·수익성을 확인한다.
4. 운영 비용을 포함한 기간 손익과 판매로 사용된 재료·남은 재료를 확인한다.
5. 기록을 수정·삭제하면 연결된 결과를 다시 계산한다.
6. 저장한 기록을 다시 사용하고, 백업 파일을 내려받거나 복원한다.

PRD의 1차 범위는 아직 ‘제안’ 상태다. 본 문서도 일·월 조회와 기록 기반 손익을 중심으로 1차 기능을 상세화하되, 이를 사용자 승인으로 간주하지 않는다. 예상 손익·발주량과 주·분기·반기·연간 조회는 누락하지 않고 2차 요구로 따로 기록한다.

## 2. 자료에서 확인한 사실

데이터설명과 JSON을 통해 다음을 확인했다. PRD의 ‘자료가 없다’는 설명은 현재 폴더 상태와 달라졌지만, 이번 작업에서 원본 PRD를 수정하지는 않았다.

| 항목 | 확인한 사실 | 기능에 미치는 영향 |
| --- | --- | --- |
| 자료 출처·기간 | 프렙 카페 가상 샘플, 2025-07-01~2026-09-18 마감. 영업달력은 9월 말까지 있음 | 이후 날짜를 확정된 판매 0으로 표시하지 않음 |
| 판매 | 6,112개 기록. 날짜·메뉴·매장/포장 채널별 수량·단가·할인·순매출·결제수수료·당시 원가 | 영수증별 주문 정보가 아니며 주문 건수를 구할 수 없음 |
| 기초 정보 | 공급사 3, 재료 11, 메뉴 8, 레시피 22, 재료가격이력 33개 | ID로 연결하며 채널별 레시피와 가격 적용일을 구분 |
| 재고 | 초기재고 11, 재고기록 1,515개. 입고·폐기·실사조정 | 입고는 양수, 폐기는 음수, 실사조정은 양수·음수. 실측수량은 별도 항목 |
| 비용 | 월비용계획 120, 비용기록 3,560개. 비용기록의 반영 방식은 ‘월비용 일할 배분’ | 계획과 일별 기록을 합산하면 같은 비용을 이중 계산 |
| 단위·금액 | g·ml·개, 원·부가세 제외. 구매가격은 구매용량 전체 가격 | 팩·kg·L 표시와 계산용 단위를 구분 |
| 미입력 | 빈칸은 해당 없음 또는 미입력. 0과 다름 | 누락된 원가·재고를 0으로 대체하지 않음 |
| 파일 관계 | 설명에 따르면 엑셀과 JSON은 같은 기록의 두 형식 | 두 형식을 각각 신규 기록으로 가져오지 않음 |
| 정책 | JSON의 settings는 비어 있음. 기존 원가·수수료·배분은 과거 기록 | 미래 정책과 분류 기준이 이미 합의되었다고 보지 않음 |

판매 자료에는 영수증 번호·시각·결제수단·취소 상태가 없다. 비용 자료에는 지급처·결제수단·고정/변동 구분이 없다. 재료 자료에는 납기·안전재고 **일수**가 있고 시안처럼 확정된 안전재고 **수량**은 없다.

## 3. PRD·시안 차이와 처리 상태

시안의 숫자·품목·상태는 예시다. 실제 기록이나 합의된 기준으로 저장하지 않는다. 버튼이 있다는 사실도 기능 승인이나 기능 완성을 의미하지 않는다.

| 차이 | 관찰 내용 | FRD의 처리 |
| --- | --- | --- |
| 판매 단위 | 시안 _3은 영수증·주문별, 자료는 일·메뉴·채널별 합계 | D01에서 합계 방식 확정. 영수증·시각·결제수단·취소 중심 시안을 일자·메뉴·채널별 목록으로 조정 필요. 양식 필수 항목·중복 정책은 별도 미정 |
| 자료에 없는 지표 | 주문 건수, 시간대 매출, 전일 동시간 비교, 취소/반품 | 1차에 자동 포함하지 않음. 시안 조정 필요 |
| 2차 기능 노출 | _1 예상 손익, _2 발주량, _4 전월 비교 등 | PRD의 2차 또는 추가 기능으로 보류 |
| 승인 없는 연동 | POS 실시간 집계, 클라우드 동기화, 외부 배달앱 직접 연동 | 구현 범위에 추가하지 않음. 상태 문구도 실제 기능에 맞게 변경 필요 |
| 승인 없는 분석 | 손익분기점, 목표 달성률, TOP 4, 4분류 매트릭스, 소진 시각, 손모 2% 경고 | 시안 전용 기능으로 보류. 목표·분류·경고 기준을 임의 적용하지 않음 |
| 보고서 파일 | _1 보고서, _2 재고, _4 메뉴, _5 비용 내보내기 아이콘 | PRD의 판매 양식·전체 백업과 별개. 추가 내보내기는 승인 전 보류 |
| 필수 화면 누락 | 백업·복원·기초 관리 본문 시안이 없음. 판매 직접 입력·수정 화면도 없음 | PRD 필수 기능으로 FRD에 포함. 화면 배치는 후속 설계 필요 |
| 기간 불일치 | PRD 일·월, _4 최근 30일 기본, _5 직접 설정 | 기간 기본값·공유 여부 미정. 30일을 이번 달과 같게 취급하지 않음 |
| 가격 변경 | _4 최신단가 재계산, 자료에는 판매 당시 원가 | 과거 실적 재계산 여부 D03 미정 |
| 비용 방식 | _5 즉시 비용/월 전체 배분, 자료는 이미 일별 배분 | 배분 방식과 과거 기록 처리 D04 미정 |
| 재고 기준 | _2 고정 안전수량과 ‘주의 20%’, 자료는 안전일수 | D06 결정 전 수치 기준을 쓰지 않음 |
| 범위 확장 | 매장 설정·사용자 아이콘·월정액 템플릿·저울 점검 | 해당 추가 기능은 승인 전 보류 |
| 시안 자체 불일치 | _1은 10월에 1/31 배분, 12일 가정과 영업 14일차 혼재. _4 88% 메뉴를 ‘낮은 마진’ 분류 | 날짜·분류 예시를 정책 근거로 삼지 않음 |

## 4. 공통 처리 요구와 예외

### 요구

- 기록을 변경하면 해당 기간의 판매·메뉴 수익성·손익·재료 결과가 서로 일치해야 한다.
- 기록 기반 결과, 추정 잔량, 실제로 센 잔량, 미래 예상치를 구분해야 한다.
- 누락 때문에 계산할 수 없는 결과와 기록이 없는 결과, 실제 0인 결과를 구분해야 한다.
- 부분 기간 조회는 실제 포함 날짜와 마감 상태를 밝혀 전체 기간 실적으로 오해하지 않게 해야 한다.

### 처리 제안 — 미확정

- 입력 검사는 저장 전에 진행한다. 잘못된 입력은 해당 칸과 이유를 알려주고 입력 내용을 유지한다.
- 저장이 성공해야 완료를 표시한다. 실패하면 기존 저장 기록을 유지하고 재시도를 안내한다. 계산 실패를 저장 성공과 혼동하지 않는다.
- 같은 저장 버튼을 연속으로 눌러도 동일 행동이 두 번 반영되지 않게 한다.
- 취소·닫기는 저장하지 않는다. 작성 중인 내용이 있으면 버리기 여부를 확인한다.
- 삭제는 대상과 영향을 알려준 뒤 확인받는다. 취소하면 기록과 결과를 유지한다. 판매 기록 삭제를 실제 환불로 취급하지 않는다.
- 검색·필터·쪽 이동은 저장 자료를 변경하지 않는다. 결과가 없으면 ‘검색 결과 없음’, 기록이 없으면 ‘기록 없음’으로 알린다.
- 표의 페이지 수와 조회 결과 전체 건수·합계를 구분한다. 필터가 합계에 영향을 주는 범위는 D08에서 결정한다.
- 입력의 필수 여부·최대값·소수 자리·파일 크기·반올림 기준은 별도 결정한다. 시안의 10MB·0.1 간격은 확정값이 아니다.

## 5. 기능별 요구사항

아래 각 기능은 사용자 행동 → 입력 → 처리 → 화면/파일 결과 → 예외 순으로 읽는다. PRD 요구를 만족하기 위한 상세 동작은 승인 전 **제안**이다. 파일 결과가 ‘없음’이면 내려받을 파일이 없다는 뜻이며, 저장 결과가 없다는 뜻이 아니다.

### F01. 메뉴·재료·레시피·가격·시작 재고 준비 및 수정

- 근거: PRD 기초 정보. _4 ‘원가 상세’, ‘레시피 연결’, ‘배합비 수정’. 백업·기초 메뉴의 본문 시안은 없음.
- 행동·입력 제안: 사용자가 기초 정보를 선택해 메뉴 이름·판매기준가, 재료 이름·기준단위·구매용량·가격, 메뉴별 사용 재료·수량·채널, 시작 재고·기준일을 준비하거나 수정한다. 가격의 적용시작일과 레시피 버전은 자료에 있는 정보다. 필수 항목과 편집 방식은 미정이다.
- 처리 제안: ID로 메뉴·재료를 연결하고 단위를 확인한다. 바뀐 정보가 적용되는 날짜 범위를 구분한다. 이미 기록된 판매 원가를 덮어쓰는지는 D03에서 정한다.
- 결과: 화면에 기초 정보와 연결/미연결 상태, 수정 결과를 표시한다. 변경한 자료는 저장·백업 대상. 별도 출력 파일 없음.
- 예외 제안: 없는 재료를 참조하거나 단위가 다르면 원가 계산을 보류하고 수정 대상 안내. 구매용량 0·음수, 음수 사용량·시작 재고는 저장 차단. 빈 레시피를 ‘원가 0’으로 인정하지 않음. 이미 쓰인 ID를 다른 메뉴로 바꾸지 않음.
- 미정: 같은 이름 허용, 0원 메뉴, 기초 정보의 신규 등록 범위, 적용일 중복, 과거 가격·레시피 수정 처리. 기초 정보 삭제는 PRD 요구가 아니므로 추가하지 않음.

### F02. 판매 기록 직접 입력·조회

- 근거: PRD 판매 관리, _3 ‘판매 기록 직접 입력’. 실제 입력 폼은 시안에 없음.
- 판매 단위 확정(D01): 날짜·메뉴·판매채널별 합계로 관리한다. 영수증·주문별 기록은 첫 버전에 포함하지 않는다.
- 입력 항목 제안: 일자, 메뉴, 채널, 판매수량, 판매당시단가, 할인총액, 결제수수료를 입력한다. 기록 식별값은 프로그램이 관리한다. 항목의 필수 여부는 별도 결정한다.
- 처리 제안: 메뉴와 해당 채널 레시피를 확인하고 순매출·재료 사용량·해당 판매의 원가를 계산한다. 저장 후 F05~F07에 연결한다. 원가 정보 누락 시 판매 자체를 저장할지 D02에서 정하며, 저장한다면 원가 미확인 상태를 보존한다.
- 결과: 판매 목록에 입력값·순매출·원가 확인 상태를 표시한다. 관련 실적·수익성·손익·재료 추정 잔량 갱신. 별도 출력 파일 없음.
- 예외 제안: 날짜·메뉴·수량 누락, 숫자 형식 오류, 음수 수량·단가·할인·수수료는 차단. 할인총액이 할인 전 판매액보다 크면 수정 안내. 수수료가 순매출보다 큰 경우 오류인지 정상 비용인지 결정 필요. 소급 입력 시 해당 날짜 이후 재고를 다시 계산하며 최근 실측과의 관계는 D05에 따름.
- 미정: 수량 0, 미래 날짜 입력, 수수료 자동 산정, 할인 단위, 미마감 기록 처리, 동일 일·메뉴·채널의 추가 입력을 합칠지 별도 보존할지. 취소·환불 기능은 승인 없이 추가하지 않음.

### F03. 판매 기록 수정·삭제·찾기

- 근거: PRD 수정·삭제·조회, _3 연필·휴지통·검색·탭·쪽 이동.
- 행동 제안: 목록에서 수정하면 기존 값을 불러오고 저장 시 변경한다. 삭제는 대상 확인 후 처리한다. 메뉴 검색과 조회 기간을 통해 기록을 찾는다.
- 처리: 기존 판매를 다시 신규 등록하지 않고 해당 기록을 변경한다. 변경 전 판매의 매출·수수료·재료 사용 영향을 제거하고 변경 후 값으로 결과를 다시 계산한다.
- 결과: 목록과 관련 기간 지표·재고가 일치한다. 삭제 후 해당 기록은 조회·집계·현재 백업에 포함되지 않는다. 별도 출력 파일 없음.
- 예외 제안: 사라진 기록 수정은 중단하고 새로 조회 안내. 저장 실패 시 기존 값 유지. 과거 마감일 수정과 최근 실사 이전 판매 삭제의 결과는 D05·D08에 따라 처리한다.
- 미정: _3 검색의 영수증 번호·결제수단, 정상/취소 탭, 정렬 아이콘은 A안 자료에 맞지 않는다. 사용 가능한 검색 항목·정렬 기준·쪽당 건수는 시안 수정 후 결정한다.

### F04. 비용 입력·수정·삭제·조회

- 근거: PRD 비용 관리, _5 직접 등록·수정·삭제·검색·카테고리·기간·초기화·저장.
- 입력: 시안은 비용 구분, 지출일, 카테고리, 항목명/설명, 금액, 지급처, 결제수단, 즉시 비용/월 전체 배분 선택을 제공한다. 기존 자료에는 날짜·분류·금액·반영 방식만 있으므로 나머지를 자동으로 채우지 않는다. 필수/선택 항목과 고정/변동 분류는 미정이다.
- 처리 제안: 저장할 비용과 손익에 반영할 비용을 연결한다. 수정·삭제 시 이전 반영을 취소한 후 재집계한다. 월 전체 배분을 선택했다면 같은 비용을 지출일 전액과 일별 배분 양쪽에 반영하지 않는다.
- 결과: 비용 목록, 기간 비용 합계, 유형/카테고리별 구성, 손익 반영 상태와 F06 결과 갱신. 유형 정보가 없는 자료는 ‘미분류’로 표시하는 안을 제안한다. 별도 출력 파일 없음.
- 예외 제안: 날짜·분류·금액 오류 차단. 환급·음수 비용은 처리 기준 결정 전 일반 지출로 저장하지 않음. 재료 구매비·이미 레시피에 포함한 포장비·판매 수수료와 비용 기록이 겹칠 수 있음을 알림. 이름만으로 자동 중복 삭제하지 않음.
- 초기화 제안: 작성한 폼만 비우고 저장된 비용은 삭제하지 않음. _5 필터는 유형·카테고리·항목/지급처로 목록을 좁히되 누락 필드를 허위 생성하지 않음.
- 미정: D04 배분 기준, 중복 비용 구분 방법, 월 경계·소급 변경, 카테고리 목록. 월정액 템플릿 자동 등록과 비용 엑셀 내보내기는 보류.

### F05. 메뉴 수익성 확인·원가 상세

- 근거: PRD 메뉴 수익성, _4 메뉴 목록·검색·원가 상세·레시피 연결.
- 행동: 기간과 메뉴를 선택하고 수익성·원가 상세를 확인한다.
- 처리 제안: 실제 판매의 순매출·판매 당시 원가·수수료를 집계하는 실적 분석과 현재 레시피·가격으로 1개를 팔 때의 참고 분석을 구분한다. 계산식은 6장 C01~C04, 최종 원가 기준은 D03이다.
- 결과: 메뉴별 판매량·순매출·재료/포장 원가·메뉴 이익·비율, 상세의 재료별 사용량·단가·비용을 표시한다. 계산 불가 메뉴의 이유와 건수 표시. 표시 단가가 현재 기준인지 판매 당시 평균인지 밝혀야 한다. 별도 출력 파일 없음.
- 예외 제안: 원가 누락 메뉴는 수익성 계산·비율·순위 대상에서 제외하되 매출·판매량 기록은 보존한다. 일부 기록만 원가가 있으면 확인된 부분과 미확인 부분을 구분한다. 매출 0이면 이익률 산출 불가, 판매 없음은 현재 기준 참고와 기간 실적을 구분한다.
- 미정: 평균 마진율 방식, 수수료 포함 여부, 기본 기간, 단위 이익 표시, 최신단가 재계산의 영향. ‘전체 매장 순이익’으로 메뉴 이익을 부르지 않음.
- 보류: Star/Puzzle/Cash Cow/Dog 분류, 목표 마진, 자동 단가 조정 권고, 별도 매트릭스·비교 분석·내보내기. ‘레시피 연결’·‘배합비 수정’은 F01로 연결하는 안이며 별도 신기능이 아니다.

### F06. 기간별 실적·매장 손익 조회

- 근거: PRD 기간별 실적·손익, _1 오늘/이번 달·날짜 선택·지표.
- 행동: 조회 기간을 선택한다. 일·월 우선 제안, 정확한 기본값·경계는 D08 미정.
- 처리 제안: 기간 내 판매 수량·순매출·원가·수수료와 비용을 한 번씩 집계한다. 비용 계획과 이미 배분된 비용은 중복 합산하지 않는다. 계산은 C05를 따른다.
- 결과: 기간·기록 마감 범위, 판매 실적, 확인된 비용, 손익 또는 산출 불가 이유 표시. 누락이 있다면 ‘확인된 부분의 참고 손익’과 미확인 범위를 함께 나타내는 안을 제안한다. 화면 지표는 자료의 메뉴·기록 단위에 맞춘다. 별도 출력 파일 없음.
- 예외 제안: 시작일이 종료일보다 늦으면 조회 차단. 미래·미마감 날짜는 ‘기록 미완료/미래’로 구분. 마감한 영업일의 판매 0과 기록 누락을 구별. 전 기간 원가가 없으면 확정 손익 표시 금지. 0 매출은 이익률 계산 불가, 손실 금액은 숨기지 않음.
- 미정: 마감 여부의 입력·변경 방법, 비용 배분, 일부 기간 집계 문구, 판매 필터와 분석 기간의 연결.
- 보류: _1 주문 건수·시간대 추이·동시간 비교·실시간 POS·손익분기점·TOP 4·목표치·보고서 내보내기. _1의 ‘예상치’는 F12이며 1차 승인 기능으로 간주하지 않음.

### F07. 재료 입고·폐기·실제 재고 기록과 잔량 조회

- 근거: PRD 재료 관리, _2 상단 기록 버튼·행별 입고/폐기/실사·공통 입력창·검색·필터.
- 입력: 대상 재료, 처리일(시각 지원 여부 미정), 수량, 단위, 사유/거래처 메모. 입고 가격·공급사 보존 여부는 자료 구조와 F01 가격 관리의 관계를 결정한다.
- 입고 처리 제안: 사용자는 양수 수량을 입력하며 프로그램은 입고 증감으로 더한다.
- 폐기 처리 제안: 사용자는 폐기량을 양수로 입력하며 프로그램은 음수 증감으로 저장한다. 기존 파일의 음수 폐기량을 다시 음수로 뒤집지 않는다.
- 실사 처리 제안: 사용자는 ‘실제로 센 총수량’을 입력한다. 실측수량과 당시 추정수량의 차이를 보여주며 잔량 조정 여부는 D05에서 결정한다. 실측 총수량을 입고처럼 더하지 않는다.
- 판매 차감 제안: 판매수량과 해당 레시피·채널을 이용해 필요한 양을 차감한다. 포장에만 쓰이는 재료는 매장 판매에서 차감하지 않는다.
- 결과: 재료별 기준일·시작 잔량·입고·판매 사용·폐기·실사조정·추정 잔량·최근 실측수량과 시점을 표시한다. 서로 다른 시점의 잔량을 같은 시점의 차이처럼 표시하지 않는다. 신규 사건을 저장하고 F06/F08에 연결. 별도 출력 파일 없음.
- 예외 제안: 재료 미선택, 단위 불일치, 입고/폐기 0 이하, 실측 음수 차단. 실측 0은 정상 입력 가능. 재고가 음수가 되면 값과 확인 필요 상태를 보여주며 임의로 0으로 바꾸지 않는다. 판매 차감량을 계산할 수 없으면 잔량은 ‘불완전 추정’으로 표시.
- 미정: 같은 날 사건 순서, 마감 실사 기준, 과거 기록 수정 후 조정 재계산, 폐기량이 잔량보다 큰 경우 저장 여부. 기존 자료는 일자만 있으므로 시각을 임의 생성하지 않음. 재고 사건의 수정·삭제는 PRD에 명시되지 않아 신규 범위로 추가하지 않음.
- _2 닫기/취소는 저장하지 않는 안. ‘저장 및 전산 반영’은 실제 저장과 계산 성공 후 완료 안내하는 안. 시안의 완료 메시지 자체는 데이터 저장이 구현되었다는 증거가 아니다.

### F08. 부족한 재료 확인

- 근거: PRD 부족 여부, _1 부족 경고·_2 부족 탭·검색·상태 열.
- 행동: 잔량을 조회하거나 부족 재료로 목록을 좁힌다.
- 처리 제안: 기준단위로 환산한 추정 잔량과 합의된 부족 기준을 비교한다. 기준 후보는 C07, D06에서 선택한다.
- 결과: 부족 재료·잔량·판단 기준·자료 시점, 계산 불가 사유를 표시한다. 부족 재료 건수는 검색 결과 건수와 구별한다. 별도 출력 파일 없음.
- 예외 제안: 기준 미설정은 ‘판단 불가’, 잔량 불완전은 ‘확인 필요’. 부족 수량을 0으로 대체하지 않는다. 단위가 맞지 않으면 비교 보류. 음수 잔량은 부족 가능성과 기록 오류 확인을 함께 안내.
- 보류: ‘주의 20%’, 위험순 자동 정렬, 손모 2% 점검·저울 점검, 예상 소진 시각. _2 실사 차이 필터는 F07 조회 방식으로 제안하되 기준 시점을 먼저 결정한다. 발주량·메모 복사는 F13이다.

### F09. 판매 엑셀 양식 다운로드·기록 가져오기

- 근거: PRD 판매 양식·가져오기, _3 기본 양식 다운로드·파일 선택/다시 선택·미리보기·중복 처리·취소·가져오기.
- 행동 제안: 양식을 내려받아 작성 → 파일 선택 → 미리보기와 행별 오류 확인 → 처리할 기록 확인 → 가져오기.
- 입력 제안: 확정된 집계 단위에 맞춰 판매일·메뉴ID·채널·수량·판매단가·할인총액·수수료를 제공한다. 이름은 식별 보조값으로 두는 안. 기록ID가 필요한지와 필수 열은 D07 결정 후 확정한다. 영수증별 구조는 포함하지 않는다.
- 처리 제안: 파일 종류·양식·필수 열과 행 값을 검사하고 F02와 같은 원칙을 적용한다. 미리보기만으로 저장하지 않는다. 알 수 없는 메뉴를 자동 생성하거나 오류 금액을 임의 수정하지 않는다.
- 화면 결과: 원본 파일명, 읽은 행 수, 정상·오류·중복·실제 반영 예정 건수, 원본 행 번호·열·이유, 최종 반영·건너뜀·실패 건수. 완료 후 판매 및 분석·재고 결과 갱신.
- 파일 결과: 판매 작성용 `.xlsx` 양식. 양식에는 합의된 열 이름·단위·입력 설명을 담는다. 가져오기는 원본 파일을 수정하지 않는다. CSV·10MB 상한은 시안의 제안일 뿐 승인 전 지원 확정하지 않음.
- 예외 제안: 깨짐·암호화·다른 양식·필수 시트/열 없음은 저장 전 중단. 빈 행은 제외하고 완전히 빈 파일은 안내. 숫자처럼 보이는 잘못된 문자열, 잘못된 날짜, 알 수 없는 메뉴/채널, 할인 오류는 행별 표시. 식별값이 같은 행과 날짜·메뉴·채널이 같은 행을 구별하며 같은 합계키만으로 중복이라고 단정하지 않음.
- 미정 D07: 오류 하나면 전체 중단할지 정상 행만 반영할지, 중복 판별 기준과 건너뛰기/덮어쓰기 지원. _3은 정상 행만 반영·중복 선택을 보여주지만 합의된 정책은 아님. 덮어쓰기는 신규 추가로 처리하지 않고 원래 판매 영향을 교체해야 함.
- 저장 도중 실패 제안: 반영 상태가 불명확한 채 재시도하지 않도록 실제 저장 건수를 확인. 전체 취소 또는 부분 성공 중 일관된 방식은 D07에서 결정. 취소·닫기·파일 다시 선택은 미확정 기록을 저장하지 않음.
- 범위: 기존 자료 전체 이전, 외부 POS/배달앱 임의 양식 지원, 비용/재고 가져오기는 F14로 보류.

### F10. 기록 저장·다시 사용

- 근거: PRD 저장. 시안의 클라우드 표시와는 별개다.
- 행동·처리 제안: 입력/수정/삭제 완료 시 저장하고 다시 프로그램을 열면 저장된 기록으로 조회·계산한다. 자동 저장인지 저장 버튼 방식인지는 D09에서 결정한다.
- 결과: 실제 저장 성공/실패와 자료 시점을 표시. 판매·비용·재고 사건·기초 정보 및 확정된 계산 정책을 유지한다. 별도 출력 파일 없음.
- 예외 제안: 저장 공간 부족·권한 문제·중단이면 저장 실패 안내와 입력 유지. 읽기 실패는 빈 새 매장으로 자동 덮어쓰지 않고 복구/복원을 안내. 화면에 계산값이 보이는 것만으로 저장 성공을 표시하지 않음.
- 미정: 한 기기/여러 기기 사용, 저장 위치·방식, 오프라인 지원. 다른 기기 공유·클라우드 동기화는 사용자 승인 없이 추가하지 않음.

### F11. 전체 기록 백업·복원

- 근거: PRD 전체 백업·복원. 시안은 이동 메뉴·백업 상태만 있고 실제 화면·입력칸은 없다.
- 백업 행동 제안: 전체 백업 실행 → 저장된 자료를 모아 파일 생성 → 파일 내려받기.
- 백업 파일 제안: 판매·비용·재고 사건·시작 재고·메뉴·재료·레시피·가격이력·필요한 달력과 확정 정책을 포함한다. 파일 작성 시각·자료 버전·포함 범위를 함께 넣는다. JSON 형식은 후보이며 D09에서 결정한다. 양식 파일은 전체 백업이 아니다.
- 백업 화면 결과: 파일 생성/다운로드 결과, 기준 시각·포함 건수. 파일 생성 성공과 사용자의 실제 파일 보관 여부를 구별한다.
- 복원 행동 제안: 파일 선택 → 형식·버전·연결 검사 → 포함 기록과 영향 확인 → 사용자가 복원 실행 → 결과 재계산.
- 복원 결과: 목록·기초 정보·손익·재고가 복원 자료와 일치하고 복원 시점을 표시. 복원 원본 파일은 변경하지 않음.
- 예외 제안: 깨진 파일·버전 미지원·다른 종류 파일·누락 필수 자료·ID 연결 오류는 복원 전 차단하고 현재 자료 유지. 복원 도중 실패 시 현재 자료를 온전하게 유지하는 방식 제안. 계산용 정보가 없는 경우 확인 필요 표시.
- 미정 D09: 현재 자료 전체 교체 또는 합치기, 복원 전 백업 방식, 초기 제공 JSON을 백업 파일로 인정할지. 다른 형식이라는 이유로 임의 변환하지 않음. 클라우드/자동 백업 상태는 실제 기능이 있을 때만 표시.

## 6. 계산 방법 제안 — 전부 미확정

계산식은 이해와 검토를 위한 제안이다. 기존 기록에 저장된 결과를 재계산할지, 그대로 사용할지 먼저 결정한다. 예시는 가상이며 시안 숫자와 일치할 필요는 없다.

| ID | 대상 | 제안 계산 | 예시·주의 |
| --- | --- | --- | --- |
| C01 | 순매출 | 판매수량 × 판매당시단가 − 해당 기록의 할인총액 | 10잔 × 4,000원 − 2,000원 = 38,000원. 할인은 총액 기준 제안. 기존 `net_sales`와 다르면 오류를 알리고 자동 덮어쓰지 않음 |
| C02 | 재료 단위 가격·원가 | 구매가격 ÷ 구매용량. 메뉴 1개 원가 = 각 재료 사용량 × 기준단위 가격의 합 | 원두 1,000g에 23,000원이면 23원/g. 20g 사용 시 460원. 해당 채널 재료만 포함 |
| C03 | 메뉴 실적 이익 | 해당 메뉴 순매출 합 − 판매수량 × 당시 식재료/포장 원가 합 − 결제수수료 합 | 수수료 포함 추천안. 식재료·포장만 차감하는 시안 방식과 다르므로 선택 필요. 매장 운영 비용은 여기서 빼지 않는 안 |
| C04 | 메뉴 이익률·평균 | 메뉴 이익 ÷ 메뉴 순매출 × 100. 전체 비율은 확인된 메뉴 이익 합 ÷ 해당 매출 합 × 100 | 38,000원 매출, 원가 4,600원, 수수료 570원이면 이익 32,830원·약 86.4%. 메뉴 비율 단순 평균 대신 판매 규모를 반영한 비율 추천 |
| C05 | 매장 손익 | 기간 순매출 − 판매 재료/포장 원가 − 판매 결제수수료 − 중복을 제거한 기간 운영 비용 | 폐기 손실을 별도 차감할지 D04 미정. 입고 대금을 소진 원가와 동시에 차감하지 않음. 원가 누락 시 전체 손익 확정 불가 |
| C06 | 재료 잔량 | 기준 시작 잔량 + 누적 입고 − 누적 판매 사용량 − 누적 폐기량 + 누적 실사조정 | 판매 사용량 = 판매수량 × 채널별 레시피 사용량. 조회 기간 전 움직임도 잔량에 포함. 단순히 그달 입출고만 계산하지 않음 |
| C07 | 부족 판단 후보 | A: 사용자가 정한 안전수량보다 잔량이 작으면 부족. B: 최근 마감 영업일 평균 사용량 × 안전일수로 안전수량 산출 | 자료는 안전일수 방식. B의 평균 기간·휴무일·판매 누락 처리 미정. 현재 자료 활용에는 B, 단순 수기 운영에는 A가 적합 |
| C08 | 실제 재고 차이 | 실제 센 수량 − 같은 시점의 추정 잔량 | 추정 1,000ml, 실측 900ml이면 −100ml. 실사 때 잔량을 900ml로 맞출지는 별도 결정 |
| C09 | 월 비용 배분 후보 | 달력일 안분: 월금액 ÷ 실제 월 일수. 영업일 안분: 월금액 ÷ 그달 영업일 수 | 300,000원/30일이면 10,000원/일. 기존 일별 배분 자료는 한 번만 합산. 원 단위 반올림 잔액 처리 미정 |
| C10 | 표시·환산 | kg↔g는 1,000배, L↔ml는 1,000배. 팩/박스는 재료의 구매용량으로 환산 | 우유 1팩=1,000ml일 때만 2팩=2,000ml. 서로 다른 재료 규격을 공통 ‘1팩’으로 처리하지 않음 |

가격 적용 제안: 새 판매의 재료 가격은 판매일 이하에서 가장 최근 적용일의 가격을 사용한다. 판매일 이전 가격이 없으면 현재 가격을 소급 적용하지 않고 계산 보류한다. 과거 자료의 당시 원가를 유지하고 현재 단가 분석은 참고값으로 분리하는 안을 추천하지만 D03 결정 전 확정하지 않는다.

0 처리 제안: 분모가 0인 비율은 ‘산출 불가’, 누락은 ‘미입력’, 정상적인 0 비용은 ‘0원’. 반올림은 계산 중간보다 표시 단계에 적용하는 안이며 원 단위 저장·집계 방식은 미정이다. 부가세 제외 샘플과 부가세 포함 새 기록을 섞지 않도록 입력 금액 기준도 확인한다.

## 7. 2차 및 시안에만 있는 기능

### F12. 예상 손익 — PRD 2차 제안

- 행동: 예상 기간과 가정을 선택해 전망 확인.
- 계산 후보: 현재까지 마감한 영업일의 일평균 실적을 남은 예정 영업일에 적용하고, 이미 기록된 실적과 합산. 월비용계획은 예상 비용 근거로 사용하되 실적 비용과 중복 합산하지 않음.
- 결과: 예상 매출·비용·손익, 사용한 기준 기간·가정·자료 마감일. 별도 출력 파일 요구 없음.
- 예외: 마감 영업일 0이면 산출 불가. 누락·휴업·비정상 판매 기간은 경고. 미래 날짜를 실제 0으로 평균에 넣지 않음.
- 미정: 기준 기간, 남은 영업일, 원가·수수료·폐기·비용 예상 방식. _1의 단순 12일 평균 및 목표치는 확정하지 않음.

### F13. 발주량 참고 — PRD 2차 제안

- 행동: 부족 재료에서 발주 참고량 확인.
- 계산 후보: 목표 잔량 − 현재 유효 잔량의 양수 부분을 구매 포장 단위로 올림. 목표 잔량 후보는 평균 사용량 × (납기 영업일수 + 안전 영업일수). 부족 확인용 안전수량과 발주 목표를 혼동하지 않음.
- 결과: 필요한 기준단위 수량·구매 포장 수량·가격을 알 때만 예상 구매액·근거. _2 메모 복사는 수량 기준 승인 후 검토할 시안 동작이며 자동 주문은 없음.
- 예외: 소비 이력·포장용량·가격 누락이면 해당 결과 산출 불가. 미입고 주문을 고려하는 기능은 현재 요구에 없으므로 추가하지 않음.
- 미정: 평균 기간, 납기 계산, 발주 주기·목표, 음수 잔량 처리. 발주서 파일 작성은 승인 전 보류.

### 확정된 첫 결정(D01)

- A. 날짜·메뉴·판매채널별 합계로 관리 **(추천)**. 예: ‘10월 12일 아메리카노 매장 판매 20잔’을 한 줄로 기록. 기존 자료를 그대로 활용하고 4시간 안에 핵심 흐름 완성에 집중하기 좋다. 주문 건수·시간대 그래프·결제수단·영수증 검색은 현재 자료에 맞춰 시안을 조정해야 한다.
- B. 시안처럼 영수증·주문별 관리. 예: ‘영수증 1번에 아메리카노 2잔과 라떼 1잔’. 주문 단위 관리는 가능하지만 기존 합계 자료를 실제 주문으로 되돌릴 수 없다. 주문 정보 구조와 새 입력 항목이 필요하므로 시간·범위 재검토가 필요하다.

답변: 사용자가 A를 선택했다. 판매 집계 단위만 확정한 것이며 입력 필수값·동일 합계키 처리·계산 기준·전체 1차 범위를 함께 승인한 것으로 간주하지 않는다.

### 다음 질문(D02): 원가 정보가 없는 메뉴도 판매를 기록할까요?

- A. 판매는 저장하고 수익성·전체 손익은 ‘계산 미완료’로 표시 **(추천)**. 예: 신메뉴 5잔의 매출은 기록하되 레시피가 없으면 이익을 확정하지 않는다. 일상 판매 기록을 놓치지 않으면서 잘못된 이익 표시를 막을 수 있다. 계산 가능한 메뉴 결과와 미확인 범위를 구분한다.
- B. 원가 정보를 먼저 채운 뒤 판매를 저장. 예: 신메뉴 레시피와 재료 가격을 등록해야 5잔을 기록할 수 있다. 모든 저장 판매의 계산 근거를 갖추지만 판매 입력이 지연될 수 있다.

답변 상태: 대기. 저장 허용·손익 표시 정책은 미정이다.

## 9. 검사 기준

결정 대기 정책은 합의 후 기대 결과를 확정한다. 다음은 반드시 검사해야 할 상황과 불변 조건이다.

| 검사 | 확인할 결과 |
| --- | --- |
| 판매 입력 → 메뉴 분석 → 기간 손익 → 재고 | 같은 판매가 매출·원가·재료 사용에 각각 한 번 반영 |
| 판매 수량·채널·날짜 변경 | 이전 영향 제거, 새 날짜/채널 레시피에 따른 결과 반영 |
| 판매·비용 삭제 취소 및 확정 | 취소 시 변화 없음, 확정 시 해당 영향 제거 |
| 원가·레시피·시작 재고 누락 | 매출 보존 여부는 D02, 계산 불가 결과를 0이나 확정 이익으로 표시하지 않음 |
| 포장과 매장 판매 | 포장 전용 재료는 포장 판매에만 반영 |
| 월 계획과 일별 비용 동시 존재 | 같은 비용을 두 번 차감하지 않음 |
| 입고·폐기·실측 0·과거 실사 이전 판매 변경 | 부호와 총수량 구분, 합의한 D05 정책 준수 |
| 정상·오류·중복이 섞인 엑셀, 동일 파일 재시도 | D07에 따른 정확한 반영 건수와 재계산, 무단 중복·덮어쓰기 없음 |
| 빈 기간·미래 기간·부분 월·연간 | 기록 없음·미마감·부분 기간·0 실적 구별 |
| 저장 실패·연속 클릭·다시 열기 | 성공 상태가 실제 저장과 일치, 무단 중복 없음 |
| 백업 후 복원 | 기록·기초 정보·정책·분석이 복원 내용과 일치 |
| 깨진 백업·지원하지 않는 파일·복원 중 실패 | 현재 자료 훼손 없이 오류 원인 확인 |
| 시안의 예시 수치·연동 상태 | 샘플 데이터나 승인되지 않은 기능을 실제 상태로 표시하지 않음 |

이 문서는 모든 PRD 필수 기능을 포함하지만 미정 정책이 남아 있어 최종 구현 기준으로는 아직 확정되지 않았다. 답변에 따라 해당 항목만 확정하고 시안과의 차이도 함께 갱신한다.
